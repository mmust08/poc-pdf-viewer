3. Feature Requirements

3.1 Multi-Page Virtualized Layout

  • Render all pages in a single scrollable container with a gap between pages.
  • Only pages within 2 viewport-heights above and below the visible area are mounted (canvas rendered). Pages outside that window are replaced by a sized placeholder <div> that preserves scroll geometry.
  • Track the current page number by comparing the scroll position against cumulative page heights. Expose currentPage (1-based) via the component's onPageChange prop callback.
  • Scroll-to-page: expose a scrollToPage(pageNumber: number) imperative handle via useImperativeHandle.

3.2 Tile-Based Rendering (per page)

  • Each mounted page is rendered as a grid of 512 × 512 px tiles (logical pixels at scale 1×).
  • Encapsulate all tile logic inside TileRenderer.ts — a plain TypeScript class with no React dependency. It must be independently instantiable and testable.
  • Only tiles intersecting the viewport (plus a 1-tile buffer on all sides) are rendered at any given time. Tiles outside the buffer are recycled.
  • No single <canvas> element must ever exceed 4096 px on either dimension. This is a hard constraint — the tile architecture must enforce it regardless of zoom level or page size.
  • Stale tile handling: when a zoom change is committed, re-parent already-rendered tile canvases into a CSS-scaled container placed behind the active tile layer. This provides instant visual feedback with zero bitmap copy. A 4-second safety timer disposes the stale container if the new tiles have not yet replaced it.

3.3 Zoom

  • Range: 10 % – 5000 % (0.1 × to 50 ×). Continuous.
  • Ctrl + wheel: zoom in/out anchored to the pointer position on the page. The page point under the pointer must remain stationary after the zoom.
  • Named zoom modes (stored as a discriminated union, not a magic number):
    • page-fit — fit the entire page height within the viewport
    • page-width — fit the page width to the container width
    • actual-size — 100 % (1 ×)
    • custom — arbitrary numeric scale set by the user or by Ctrl+wheel
  • A ResizeObserver on the container must re-apply named modes whenever the container is resized, so page-fit and page-width remain accurate after layout changes.
  • Expose a zoom prop (controlled) and an onZoomChange callback, plus an uncontrolled default.

3.4 Pan

  • Right-click drag to pan. This deliberately keeps left-click free for mark interactions. Suppress the browser context menu during right-drag.
  • Momentum / inertia is not required, but the pan must feel responsive (no debounce on mousemove).

3.5 Mark Interactions

  • Marks are rendered on an SVG overlay sized to the page (not the viewport).
  • Add: left-click on the page (not on an existing mark) places a new mark at the clicked page coordinates.
  • Select: left-click on an existing mark selects it. Only one mark may be selected at a time. Clicking the selected mark deselects it.
  • Drag to reposition: after left-click-down on a mark, dragging moves it. Use setPointerCapture so the drag works even when the pointer leaves the mark's hit area.
  • Visual differentiation:
    • Each mark's fill color is derived from a hash of its label string (deterministic, same label → same color across sessions).
    • Non-selected marks render at 35 % opacity when any mark is selected.
    • The selected mark renders at full opacity with a distinct stroke.
  • Info panel: when a mark is selected, show a small panel (positioned near the mark or in a fixed corner) displaying the mark's label and its page coordinates (in PDF user units, not screen pixels).
  • Marks are per-page. The marks prop shape: 
    type Mark = {
  id: string;
  page: number;        // 1-based
  x: number;           // PDF user units
  y: number;           // PDF user units
  label: string;
};
  • Expose marks (controlled) + onMarksChange(marks: Mark[]) callback.

3.6 Rendering Smoothness

  • Scroll listener must use requestAnimationFrame throttling — never fire more than once per frame.
  • Tile re-render after a zoom commit must be debounced: wait 120 ms of committed-scale stability before dispatching tile render jobs.
  • Off-screen canvas double-buffering inside TileRenderer: render into an off-screen canvas first, then transfer/swap to the visible canvas atomically to prevent flicker.

4. Public Component API

interface PdfViewerProps {
  // Source
  src: string | ArrayBuffer | Uint8Array;

  // Zoom (controlled or uncontrolled)
  zoom?: ZoomMode;                          // ZoomMode = 'page-fit' | 'page-width' | 'actual-size' | { type: 'custom'; scale: number }
  defaultZoom?: ZoomMode;
  onZoomChange?: (zoom: ZoomMode) => void;

  // Marks (controlled)
  marks?: Mark[];
  onMarksChange?: (marks: Mark[]) => void;

  // Page
  defaultPage?: number;
  onPageChange?: (page: number, total: number) => void;

  // Layout
  className?: string;
  style?: React.CSSProperties;
}

// Imperative handle
interface PdfViewerHandle {
  scrollToPage(page: number): void;
  getPageCount(): number;
}

// Usage
const ref = useRef<PdfViewerHandle>(null);
<PdfViewer ref={ref} src="document.pdf" defaultZoom="page-width" />

5. Code Quality Requirements

  • MUST: TypeScript strict mode — zero any types.
  • MUST: TileRenderer has zero React imports — it is a plain class usable outside React.
  • MUST: useMarks and usePageLayout are standalone hooks, each in their own file.
  • No comments explaining what the code does — only add a comment when a constraint or workaround is non-obvious.
  • No console.log left in production paths.
  • Clean up all addEventListener, ResizeObserver, RAF loops, and PDF.js render tasks in their respective useEffect return functions.
  • Abort in-flight PDF.js render tasks on zoom change to prevent race conditions. Use renderTask.cancel().

6. What NOT to Build

  • No print functionality
  • No text selection layer
  • No annotation layer (PDF.js built-in)
  • No thumbnail sidebar
  • No keyboard shortcuts beyond what's needed for zoom (Ctrl+wheel)
  • No touch / pinch-zoom support (desktop only)
